# FIT Brand — Design principles

## The six principles

### 1. Clarity before decoration
Every visual element either carries information or it should not exist.
If removing an element makes the layout cleaner without losing meaning,
remove it.

### 2. Systems should look like systems
FIT builds operational systems, not consumer apps. Layouts should reflect
structure: clear hierarchy, predictable patterns, legible information architecture.
Avoid organic, editorial, or artistic layouts for operational interfaces.

### 3. Show flow, not friction
The path forward is always obvious. Primary actions are visually dominant.
Secondary options recede. The user should never have to search for what to do next.

### 4. Make status unambiguous
Approved, draft, pending, and published are always visually distinct.
Use fit-green for approved/complete states. Use amber/yellow for pending.
Use fit-blue for active/in-progress. Never rely on text alone to communicate status.

### 5. Human oversight must be legible
Wherever a human must review, approve, or intervene — that point is visually
marked. Approval gates are never hidden in a flow. The human in the loop
should always know they are the human in the loop.

### 6. Use colour with intent
Colour encodes meaning. fit-green means approved. fit-blue means active.
Do not use these colours decoratively. A page with less colour is often
more legible than one with more.

## Application checklist

Before shipping any designed output:
- [ ] Can every visual element justify its presence?
- [ ] Is the primary action on this screen immediately obvious?
- [ ] Are all status states visually distinct?
- [ ] Are approval/review points clearly marked?
- [ ] Does colour usage follow the intent rules?
- [ ] Does this look like a FIT system?

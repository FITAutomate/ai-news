# AI News Pulse

AI News Pulse is a weekly AI briefing site for high-level, actionable updates.

## Repo standards

This repo follows the FIT Automate `.agent/` standards layout. Operating rules live in:

- `.agent/AGENT.md` -- canonical operating rules
- `.agent/CONTEXT.md` -- repo context, layer-1 reference, enabled skills
- `.agent/COMMANDS.md` -- sanctioned PIV validation commands

PRP artifacts (PRDs, plans, issues, reports, reviews, evidence) live under `.agent/prp/<bucket>/`.
Issue templates and the label manifest live under `.github/`. Active PRP: see issue `#3` and
`.agent/prp/prds/2026-06-06-ai-news-hyperagent-bootstrap.prd.md`.

Root `AGENTS.md` and `CLAUDE.md` are thin pointers to `.agent/`.

## What this repo contains

- A static site (`index.html`, `styles.css`, `app.js`)
- Current week data in `news-data.json`
- Archived weeks in `archive/news-YYYY-WW.json`
- An archive index at `archive/manifest.json` (regenerated by script; drives the week selector)
- A reusable weekly curation workflow in this README and in `skills/ai-news-weekly/`

## Tooling contract

Everything here is **static, JSON-driven, and portable**. You only need:

| Need | How |
|------|-----|
| Edit data | Editor or agent with repo file access |
| Validate weekly JSON | `node skills/ai-news-weekly/scripts/validate-news-json.mjs news-data.json archive/news-YYYY-WW.json` |
| Refresh week list after adding/changing archives | `node scripts/sync-archive-manifest.mjs` (repo root) |
| Map a calendar date to a week key (optional) | `node scripts/week-key-from-date.mjs YYYY-MM-DD` |
| Curate new links | Optional web browser or search; **no** MCP or database is required by the repo |
| Publish | `git` push to `main` (GitHub Pages) |

## Quick start

1. Clone the repo:

```bash
git clone https://github.com/FITAutomate/ai-news.git
cd ai-news
```

2. Serve locally with any static server.

Python:

```bash
python -m http.server 8080
```

Node (optional):

```bash
npx serve .
```

3. Open:

`http://localhost:8080`

## Current behavior

- Homepage defaults to `news-data.json` (current week)
- Week selector loads archive weeks listed in `archive/manifest.json` (built from `archive/news-*.json`)
- Each story card links to its primary source (`Read source`)
- Links open in the same tab
- Cards display:
  - category emoji
  - rating stars
  - tags

## Data schema (`news-data.json`)

Top-level fields:
- `meta.updatedLabel`
- `meta.dataDate` (YYYY-MM-DD)
- `meta.window`
- `meta.themes`
- `news[]`

Each `news[]` item:
- `category`
- `date` (YYYY-MM-DD)
- `title`
- `summary`
- `source`
- `sourceLabel`
- `rating` (1-5)
- `tags` (array of 2-5)

## Weekly curation plan

### Goal

Publish a weekly AI summary that is high-level, useful, and worth clicking through.

### Output target

- Preferred: 12 stories (3x4 grid)
- Minimum: 9 stories (if the week is genuinely quiet)
- Keep stories diverse and non-repetitive week-to-week

### Priority topics

- Agentic workflows, tool use, coding agents
- RAG, retrieval, vector DBs, evaluation, governance
- Automation stack: n8n, Airtable, Make, Zapier, MCP, orchestration
- Practical security workflows and controls
- Infra affecting cost/performance: GPUs, NPUs, TPUs, Trainium, inference, serving

### Weekly mix target (12-card goal)

- 3 model/platform updates
- 3 business/market signals
- 2 infra/chips stories
- 1 policy/regulation story
- 3 builder workflow stories

### Credibility and diversity rules

Choose stories that are:
- Credible (official posts first, then major outlets)
- Important (strategy, spend, roadmap, regulation)
- New (avoid repeating last week's same point)
- Diverse (not all from one vendor)

Selection constraints:
- Max 2 stories per major vendor category per week
- Max 1 story per vendor in the top 3 cards
- Avoid duplicate angles of the same announcement

### Weekly workflow

1. Gather 20-30 candidate links across product, markets, infra, policy, and builder workflow buckets.
2. Score each candidate:
   - `5★` direct stack impact or major model/platform shift
   - `4★` strong practical signal likely to matter soon
   - `3★` useful but not urgent (only if needed to hit minimum)
3. Select top 9-12 stories while preserving mix and diversity.
4. Update `news-data.json` (`meta` + `news`).
5. Create archive file: `archive/news-YYYY-WW.json`.
6. Run `node scripts/sync-archive-manifest.mjs` so `archive/manifest.json` includes the new week.
7. Run local smoke test and verify rendering + week selector behavior.
8. Commit and push (include `archive/manifest.json` when the archive set changed).
9. Confirm GitHub Pages deploy.

Suggested commit message format:

`AI News Pulse: weekly update YYYY-MM-DD (Week WW)`

## Visual tuning

Background image visibility is controlled in `styles.css` in the `body` background stack.

Primary overlay control:

```css
linear-gradient(rgba(0, 0, 61, 0.66), rgba(0, 0, 61, 0.74)),
```

- Lower alpha values to reveal more of `news-bg.png`
- Raise alpha values to darken for stronger text contrast
- Small changes (`0.03` to `0.08`) are usually enough

Suggested presets:
- Slightly more visible: `0.66 / 0.74`
- More visible: `0.60 / 0.68`

Secondary glow controls:

```css
radial-gradient(circle at 10% 10%, rgba(0, 124, 232, 0.27) 0%, transparent 42%),
radial-gradient(circle at 88% 14%, rgba(28, 208, 0, 0.18) 0%, transparent 34%),
```

- Lower these values for less color glow over the photo
- Re-test readability on cards and small text after changes
